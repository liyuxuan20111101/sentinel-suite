# RCA 结论（示例答案，用于演示评分器）

**根因**：Redis 实例 redis-cache-prod-3 内存打满（maxmemory 32GB），14:10 起 allkeys-lru 大规模淘汰热 key（evicted_keys 从 0 飙到 41 万，命中率 0.97 → 0.38）。订单详情缓存被击穿后，请求直接打到 DB，连接池 198/198 打满，p99 从 180ms 涨到 5.2s。

**为什么不是发布**：14:02 的 v2.31.0 只增加了只读的积分展示字段，不产生额外缓存写入压力；内存曲线在 13:40 就已到 0.86，发布只是恰好提前了临界点的到来。

**处置建议**：
1. 立即：把 maxmemory 上调或清理大 key（注意当前 allkeys-lru 会持续淘汰热 key）；
2. 短期：评估淘汰策略与 TTL 分布，给订单详情热 key 设置合理过期，避免同时失效；
3. 长期：为缓存容量增加水位告警（0.85 而不是 1.0）。
