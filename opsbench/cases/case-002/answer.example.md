# RCA 结论（示例答案，用于演示评分器）

**根因**：数据库连接泄漏。v5.7 新增的"最近登录设备"查询在事务里打开连接后没有归还——pg 侧 `idle in transaction` 从 2 堆到 198/200，应用连接池耗尽（pool exhausted, pending 87）。泄漏周日就上线了，周一早高峰的流量把它顶过临界点，所以"周一时才炸"不代表是周一的变更。

**传播链**：连接池耗尽 → 获取连接的请求挂起/报错 → 登录接口 30% 500 → 健康检查失败 → 实例被摘除，完全不可用。重启应用强制归还连接所以"重启就好"。

**处置建议**：
1. 立即：给 PG 设 `idle_in_transaction_session_timeout`（如 60s），把挂死的连接先掐掉；
2. 代码修复：该查询改用 `with` 上下文管理或 `try/finally` 确保连接归还；确认没有在只读查询外开事务；
3. 治理：连接池加 `pool_pre_ping` 与获取超时，DB 侧对 idle_in_transaction 加告警（>50 即报）。
