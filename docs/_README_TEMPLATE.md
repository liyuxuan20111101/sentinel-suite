# README 写作模板（发布时按此改主 README）

> 发布前把本文件删掉。它只描述"README 该怎么写"，不进仓库正文。

你的主 README 已经有了骨架：一句话定位 → 五工具表 → 快速开始 → 状态与诚实声明 → 许可。
发到 GitHub 前，按下面几条补强，从"能用"变成"有人愿意用"：

## 1. 顶部加一段"为什么存在"（最重要）

读者 30 秒内决定要不要往下看。别罗列功能，说清你针对的**行业现状**：

> LLM 生成的代码正在大批进入生产环境，但"测试全绿"不等于"行为没变"——SWE-Proof
> 证明约 25% 的通过测试的补丁仍可构造反例。review 意见可以生成，行为证明没有人做。
> DiffVerifier 补这一块。

每个工具一句"行业缺什么 + 我补什么"。这五个的定位语你都有了（就是现在表格里的
"立身之本"列），直接用。

## 2. 放一张实测输出截图

Web 前端跑一次 DiffVerifier（行为差异被标红的那种），截输出面板。图片放
`docs/screenshot.png`，README 里 `![DiffVerifier 检出行为差异](docs/screenshot.png)`。
一张"问题被抓住"的截图胜过十行描述。

## 3. 快速开始保持"复制即跑"

现在的命令已经是可复制的，保持住。新增内容时守住纪律：
**每条命令必须测过**。README 里第一条命令就报错的项目，没人看第二眼。

## 4. 加"与 X 的区别"小节（可选但加分）

- 与 `pytest`：pytest 验证"新代码符合预期"，DiffVerifier 验证"新旧代码行为是否一致"——
  后者不需要你写断言，只要给输入。
- 与 `pip-audit`：pip-audit 查**已安装**包的已知漏洞，SlopFirewall 查**将安装**的包名
  是否存在——一个是漏洞库比对，一个是幻觉门禁，互补。
- 与 langfuse/LangSmith：它们做观测（看得到），ReplayKit 做重放（跑得起来）。

## 5. 诚实声明放在显眼处（不是文末）

你已有的"状态与诚实声明"段落是对的，往前挪到快速开始之后。带边框引用：

> ⚠️ 诚实声明：v0.1 的 PostTrain-Doctor 是启发式指纹，不是论文指标复现；
> OpsBench 是关键词级评分，会被同义表述漏判。每个数字的定义都在代码里，欢迎反驳。

这是这个仓库和其他"ML 工具箱"最大的差异点——维护它。

## 6. 引用格式（如果希望被学术/报告引用）

文末加一节 Citation（APA/BibTeX），只引本仓库；论文动机引用写进正文链接即可。
